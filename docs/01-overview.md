# 01 · 插件总览

## 定位

ReportDesk 是一个**举报工作台**插件，把 Minecraft 服务器里"玩家举报 → 管理员处理 → 结案归档"这条流程完整产品化。它不是简单的 `/report <玩家>` 一行命令，而是一套 GUI + 命令 + 工作流 + 存储 + 审计 + 通知的组合。

## 解决什么问题

- **玩家侧**：举报门槛低、入口统一。一个 `/report` 打开 GUI，选对象、选分类、填详情，30 秒完成。支持聊天违规多选、离线举报、自己的举报列表与回复。
- **管理侧**：受理有工作流（认领 → 处理 → 结案），有优先级与 SLA 超时提醒，有审计日志记录每个管理动作，有关注列表盯住惯犯。
- **运维侧**：所有数据异步落盘，主线程零 IO；配置全部外置，游戏内可热改；存储格式人类可读（YAML/JSON），方便备份与迁移。

## 设计原则

1. **基础功能永远可用**：举报、受理、存储、通知不依赖任何增强层开关，默认配置开箱即用。
2. **增强层默认全关**：证据采集、轨迹、自动检测、处罚全部 `enabled: false`，且**关闭时入口一次开关判断直接返回**，不读子配置、不注册高频事件、不产生额外主线程开销。
3. **零魔法数**：所有业务阈值（冷却、上限、保留天数、分页、自动关闭…）都在 `config.yml`，代码只读配置并提供默认值与非法值校验。
4. **主线程零 IO**：举报写入、审计写入、证据落盘全走独立异步线程池，GUI 与命令处理不会因存储卡住。
5. **人类可读的数据**：`reports.json` + 追加式 `reports.log`（WAL），备份与压缩策略可配，误删有备份兜底。

| 许可 | GPL-3.0-or-later |

## 与典型举报插件的差异

- 多数插件只做"提交 + 列表"，ReportDesk 是**完整受理工作流**（认领、SLA、审计、回复串）。
- 证据采集是**可选增强层**而非默认行为，服务器可以只在需要时打开，平时零开销。
- 配置 100% 外置且**游戏内可热改**（`/reports config set`），不用每次进后台改文件重启。
