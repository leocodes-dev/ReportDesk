# 07 · 多语言（i18n）

## 机制

插件所有**自带文案**（提示、GUI 标题、审计摘要…）都放在 `lang/<language>.yml`，通过 MiniMessage 渲染。`config.yml` 的 `language` 键决定加载哪份：

- `zh_CN` → `lang/zh_CN.yml`
- `en_US` → `lang/en_US.yml`
- 缺失或非法值 → 回退 `zh_CN`

### 三层合并

加载时按以下顺序合并（后者覆盖前者同 key）：

1. **bundled**（jar 内置 `lang/<language>.yml`）— 保证升级后新 key 一定在；
2. **fallback**（另一份内置语言）— 提供结构兜底；
3. **primary**（磁盘上的 `plugins/ReportDesk/lang/<language>.yml`）— 管理员自定义。

嵌套 YAML 会被展平成 `dot.separated.key`；未命中的 key 返回 key 本身（不会崩溃）。

## 文件结构

```yaml
# lang/zh_CN.yml（节选）
general:
  none: '<gray>无'
  reload-ok: '<green>配置已重载'
prefix: '<dark_aqua>[ReportDesk]<reset> '

report:
  success: '<green>举报已提交'
  cooldown: '<red>请稍后 %seconds% 秒再试'

categories:
  cheating:
    name: '<gold>作弊 / 外挂'
    description: '<gray>飞行、加速、自动点击、透视等'
```

- `prefix`：所有提示的前缀；
- `general`：通用文案；
- `report` / `admin` / `gui` / `webhook` / `time`：各模块文案；
- `categories.<id>.name` / `.description`：**分类本地化**（见下）。

## 分类本地化（重点）

分类的**显示名与描述**优先读语言文件，取不到才回落 `config.yml` 的 `display` / `description`：

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1 | `lang/<language>.yml` → `categories.<id>.name` | 语言文件有条目就用它 |
| 2 | `config.yml` → `reports.categories.<id>.display` | 兜底 |

`description` 同理：`categories.<id>.description`（语言）→ `reports.categories.<id>.description`（config）。

**为什么**：`config.yml` 的 `display` 本质是数据（服务器可自定义），不是插件文案；语言文件才随 `language` 切换。这样"内置 7 分类"切语言会跟着变，而"你自己新增的分类"没写语言条目时自动用 config 里的 `display`。

### 新增分类后要做的事

1. `config.yml` 加 `reports.categories.<新id>`（display/icon/aliases…）；
2. `lang/zh_CN.yml` 与 `lang/en_US.yml` **两边都**加 `categories.<新id>.name` 和 `description`（保持 key 镜像，否则某语言下会回落 config）；
3. `/reports reload`。

## 占位符

消息模板用 `%name%` 记法，渲染时自动转成 MiniMessage 的未解析占位符（玩家输入不会被当作 MiniMessage 解析，防注入）：

```yaml
cooldown: '<red>请稍后 %seconds% 秒再试'
own-line: '<gray>#<white>%id%</white> %priority% ...'
```

## 添加新语言

1. 复制 `lang/en_US.yml` 为 `lang/fr_FR.yml`，翻译内容；
2. `config.yml` 设 `language: fr_FR`；
3. 重启或 `/reports reload`。

新语言文件缺失的 key 会自动走三层合并回退到内置默认，不会出现整页空白。

## 校验

`MessagesTest.bundledLanguageFilesContainEveryMessageKey` 反射遍历 `MessageKeys` 的每个常量，断言它**同时**存在于内置的 `zh_CN.yml` 与 `en_US.yml`。`MessageKeys` 是 900+ 个 key 常量的单一来源，避免散落的字符串拼错。新增文案 key 时：在 `MessageKeys` 加常量 → 两个语言文件各加一项 → 测试会自动要求两边齐全。

## 已知设计取舍

- `punishments` 的 `%reason%` 占位符会带入举报详情原文（已校验长度/非法字符，但内容本身可控）；这是为了让处罚命令能引用原因，属文档化的取舍，非 bug。
- 分类 `display` 改英文兜底（`config.yml`），语言文件负责本地化，避免 config 里再藏一份中文。
